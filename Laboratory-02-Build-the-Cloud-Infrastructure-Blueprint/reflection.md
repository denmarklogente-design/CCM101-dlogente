# Reflection

This laboratory activity helped me understand cloud infrastructure through actual hands-on experience. Using the KillerCoda Playground allowed me to explore a Linux server and examine the resources that are available in a cloud-like environment. This made the concepts easier to understand because I was able to see real system information through the terminal.

For me, **compute resources** are one of the most important parts of cloud infrastructure because they are responsible for processing tasks and running workloads. The CPU, CPU core, and RAM provide the resources needed for the server to perform different operations. Without enough computing capacity, applications may not be able to run properly.

I also learned how Linux can be used in cloud computing. The Linux terminal provides commands that make it possible to inspect different parts of a server. During the activity, I used commands such as `cat /etc/os-release`, `uname -r`, `nproc`, `free -h`, `df -h`, `findmnt`, `hostname`, and `hostname -I`. Each command gave me specific information about the system.

Another thing I learned is the importance of technical documentation. Recording infrastructure information in a structured way makes it easier to understand, review, and maintain a system. Documentation can also provide useful information when changes or troubleshooting are needed.

I developed several skills during this laboratory, including using Linux commands, identifying server resources, organizing technical information, creating Markdown tables, comparing cloud providers, and managing files through GitHub.

My GitHub portfolio also became more complete because I was able to document my infrastructure investigation, cloud provider comparison, cloud components, diagram, and reflection. Overall, this activity gave me more confidence in working with Linux and helped me better understand how different cloud infrastructure resources work together.
